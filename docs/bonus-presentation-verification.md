# Bonus and animation verification

These checks concern Wingrid only. The archive and starlight-rebuild are not implementation targets.
Payout rules and probabilities remain Wingrid's own play-credit rules.

## Repeatable checks

Run `npm test` for payout, transaction, win-tier, maximum-win signal, shared animation
clock and asynchronous audio regressions. Run `npm run build` for the production bundle.

Run `node scripts/presentation-fixtures.mjs /tmp/wingrid-presentation.json` for deterministic
responses generated by the real round functions. In the local browser, temporarily intercept
only `/api/spin` and `/api/jackpot/pick` with these responses. Reload afterwards to remove the
interception. Do not use test responses against production. Fixed-seed cases are deliberately
independent scenarios; they do not represent a probability model or one naturally continuous feature.

Local development exposes `__wingrid.scene`, `__wingrid.presentation`, `__wingrid.bonuses`,
and a read-only copy of the current state for targeted visual checks. These are excluded from production.

## Requirement evidence

| Requirement | Verification |
| --- | --- |
| SCATTER anticipation | Three scatters in early columns delay later columns, animate orbiting stars and glow, cue a rising tone and the brown-haired mascot's anticipation pose. A failed threat also returns to idle. |
| Mascot reactions | Observe `v2_anticipation`, `v2_win`, `v2_spell`, `v2_bonus`, then idle. These deform the approved brown-haired mesh; no old portrait is rendered. |
| Multiplier collection | Winning orb copies follow curved trails to the HUD. 2/12/50/250x orbs produce 314x and green/blue/pink/yellow meter effects. Values remain above orb animations. |
| Win tiers | 20/35/50/100x select Nice/Big, Superb, Mega and Sensational. Larger awards progress through every reached tier, with entry, loop, exit, counter and sound. |
| Maximum win | A capped feature whose last spin pays 0.01 still celebrates its full 5,000x total. The server supplies `maxWin`, independently of `feature-end`. |
| Feature presentation | Natural and bought starts, +5 retriggers and results use animated banners. Entry and exit play the screen wipe and change backgrounds. Buy supports affirmative and negative animations. |
| Jackpot presentation | All four tiers complete: logo/reel in and loops, all four face flips, anticipation at two matches, three matching win frames, tier in/loop/out, payout counter and sound, reel/logo exit. |
| Standard symbols | All nine symbols play their individual landing, win and exit poses alongside common win frames and disappearance effects. |
| Speed | Changing speed updates active Spine states and the remainder of tweens/counters using one clock. CSS flips use the same speed. |
| Audio recovery | A feature resumed before user interaction starts free music on unlock. Stale music/count loads do not start after their event has ended. |

Browser verification used the local Vite/Worker server at `http://127.0.0.1:8796`,
with desktop and 390×844 portrait viewports, including actual purchase/free-spin playback
and deterministic rare-event responses. Runtime animation names were recorded during playback;
these checks verify event wiring as well as asset availability. Screenshots and runtime journals
are saved in the ignored `.backups/animation-*` files.

A separate local QA guest exercised the real D1/API reload path: two Grand jackpot
cards restored on load, the remaining picks credited 2,500 once, and the award row
had one claim. A server-backed feature also resumed with audio still locked;
the first interaction changed the audio context to running and fetched free-spin music.
The prior browser session was restored after these checks. Keyboard purchase cancellation,
win-counter skipping, feature continuation and the reduced-motion presentation were checked.
